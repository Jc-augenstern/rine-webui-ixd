# IXD 性能分析 · 2026-09-20

仅分析，未修改应用源码、用户偏好、画质或动效。性能采样运行于独立浏览器上下文；60 FPS 调度实验只在测试页面临时注入。开发预览服务器为 5173，生产构建预览为 4173。生产包来自上一轮已通过构建的 IXD 版本。

## 测试范围与限制

- Chromium 153.0.8010.48，Windows / ANGLE D3D11，NVIDIA GeForce RTX 5070 Ti Laptop GPU。
- 1920×1080、DPR 1，每场景采样约 6 秒；连续切档每 450ms 一次。
- Service Worker 在隔离上下文中禁用，避免离线包下载干扰渲染测量；未改实际站点的 PWA。
- 帧率是 requestAnimationFrame 回调采样，不是显示器真实呈现帧数或所有设备的性能保证。主线程忙碌度由 CDP TaskDuration / elapsed 计算，**不是系统任务管理器的总 CPU 百分比**。
- 未直接测量 GPU 毫秒、整机功耗或真实显存；不能将 CPU、帧率和三角形计数单独解释为某个 GPU pass 的精确占比。
- 原始结果：[ixd-performance-2026-09-20.json](ixd-performance-2026-09-20.json)。测试脚本保存在本地 `.tools/ixd-perf-probe.cjs` 与 `.tools/ixd-perf-confirm.cjs`。

## 实测摘要

| 场景 | 每秒回调样本 | 主线程忙碌度 | 绘制/帧 | 三角形提交/帧 |
| --- | ---: | ---: | ---: | ---: |
| IXD 预览循环 | 170.6 | 19.9% | 无 WebGL | 无 |
| IXD 预览暂停 | 299.7 | 2.9% | 无 WebGL | 无 |
| 生产版阵列无操作 | 81.4 | 74.4% | 75 | 约 426–430 万 |
| 生产版连续切档 | 27.8 | 64.4% | 126–432 | 约 450–583 万 |
| 超级模式阵列无操作 | 101.5 | 67.7% | 43 | 约 145–146 万 |
| 超级模式连续切档 | 35.1 | 72.9% | 43–241 | 约 146–237 万 |
| 独立查看器无操作 | 107.6 | 52.1% | 持续渲染 | 未单独采集 |

三角形数字包含阴影、深度、折射等多次提交，**不是模型独立面数**。独立查看器打开时 `window.rhine.stats()` 仍返回暂停的主场景计数，原始 JSON 中该场景的 calls/triangles 不能当查看器计数使用。超级模式后的第二张 1920×1080 canvas 属于关闭后保留的查看器上下文，不代表它仍在绘制。

快速切档 p95 回调间隔：原始约 109.8ms，超级模式约 56.6ms。说明单纯降低画质未消除切档成本；不同轮次的 CPU 负载、频率、编译缓存也会影响绝对值，不能将这一轮数字当固定提速比例。

详情进入后短样本仍重绘，但进一步等待 18 秒后，接下来的 6 秒里 **0 次三维重绘、1,771 次复用**。其静态复用实际有效；不要把进入过程的余量收敛误诊为永久失效。

预览循环期间 6 秒 **1,025 次布局计算**；暂停后为 0。测试性约 60 FPS 更新得到 359 次回调 / 6 秒、360 次布局、主线程忙碌度 **10.82%**。即使降低更新率有效，仍应继续减少重复 DOM 写入。该实验没有修改源码。

## 瓶颈与优先级

### 1. 当前动效预览：高频 SVG/DOM 更新

`src/ixd-preview.ts:18–27,45–52` 默认每 4.8 秒循环，没有网页帧率限制。每帧重写按钮、时间、阶段类、状态文本等；`src/ixd-mark.ts:39–58` 完成成形后仍重写相同路径状态。暂停仍有空 RAF，但不再布局。

优先改为：状态变化才写 UI；成形后的 SVG 不重复更新；暂停时取消调度；时间数字降低更新频率。可选 60 FPS 上限会改变高刷新率屏幕的帧节奏，应与保持当前完整动态分开评估。此预览没有 Three.js、GLB、音乐或 PWA，不能将它的开销归因于三维模型。

### 2. 主站：持续呼吸与物理玻璃 / 后处理叠加

`src/scene.ts:1253–1267,1309–1314` 无操作 2.5 秒后自动呼吸，实例矩阵持续改变；采样中约 316 张卡实际绘制，约 456 张候选。`src/scene.ts:1704` 因矩阵变化跳过静帧复用。

默认 `src/render-quality.ts:26–35` 为 2048 阴影、32 样本全分辨率 AO、景深、全分辨率物理折射、DPR 上限 1.5。`src/scene.ts:310–325` 组合多道渲染；实际高分屏像素成本可进一步增加。这是持续成本重点，不能只看 40 份逻辑档案数量。

无损优先：缓存不变的矩阵/投影/裁剪工作、不可见 HUD 提前返回、对相同 DOM 状态停止写入。静置降帧、关闭呼吸或简化远景物理玻璃属于行为或画质折中，需逐项对照。

### 3. 快速切档：归位副本放大绘制调用

每 450ms 切换的样本最高出现 432 次绘制调用，明显高于闲置的 75 次。归位过程中的多个完整卡片同时存在，保留物理材质和多道渲染，造成瞬时峰值。优化应保留原有“先归齐再下降”的连续动作，评估副本材质共享、重复工作缓存和远景层级，避免直接截断动画。

### 4. 独立查看器：没有静态按需绘制

`src/model-viewer.ts:554–620` 无操作仍更新部件、渲染，并每帧序列化完整统计到 dataset。可优先增加静态复用，输入、过渡、拆解、主题及尺寸变化时唤醒，诊断统计降低频率。

关闭时释放模型与标签，保留 renderer/后处理/环境贴图供重开；这是有界缓存，不足以认定泄漏。主站在查看器打开时停止自己的场景更新（`src/main.ts:959`），并非两套三维同时渲染。

### 5. 加载和内存是另一类问题

- 主 GLB 3.40 MiB / 原始 86,154 三角，独立查看器 GLB 3.19 MiB / 原始 82,346 三角，无嵌入纹理。后者首次打开查看器才加载。
- 背景单卡五种保留几何共 4,200 三角，紧固件 2,136，占约 51%；远景螺丝可作为 LOD 候选，但属于模型细节取舍。
- 主站 JS 约 1.03MB（gzip 312KB），CSS 667KB（gzip 206KB）；字体声明占 CSS 大部分。
- 当前预览首次页面资源约 1.16MiB，主站进入阵列约 5.31MiB（不含被禁用的 PWA 离线下载）。字体按字集请求，不是首屏全部加载。
- 完整 PWA 离线包 33.89MiB / 818 文件，字体占 24.08MiB；它影响生产站的首次离线准备，不解释开发预览的持续渲染消耗。
- 三条背景音乐若全部解码，按源采样率推算 PCM 约 58.59MiB；实际受 AudioContext 采样率影响，未在本轮直接测内存。静音缓存不等于泄漏。

## 建议推进顺序

先做不改变画面的调度、不可见元素及重复工作优化，再独立验证 60 FPS / 静置降帧；最后才考虑 AO、折射分辨率、远景细节。现有超级性能模式可临时减负，但有玻璃层次和阴影的损失，且不能独自解决切档峰值。保留现有后台暂停、实例化、裁剪、共享深度和详情静态复用。
