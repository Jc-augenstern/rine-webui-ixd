# IXD Website Design Specification

本文保存已确认、相对稳定的设计与工程原则，不记录逐轮开发过程、当前 bug 或具体调参。工作规则见 [AGENTS.md](../AGENTS.md)，实现快照、运行方式与历史资料索引见 [CURRENT_STATE.md](CURRENT_STATE.md)。只有用户明确改变设计原则或项目规范时，才相应更新本文。

## 1. 项目定位

IXD 网站以交互设计社团初稿为内容基础，通过 **IXD ANALYSIS OS → 星门 → 银河星图** 提供社团内容与协作平台。公告、赛事、项目、活动、学习与作品由同一 PostgreSQL 数据库及独立后台维护；社团方向、成长路径与参与方式保留在空间体验中。启动、身份确认和星体探索共同构成沉浸式体验；星辰是内容入口，终端是阅读与操作界面。

保留这一空间叙事，不将主页自行改成普通顶部导航、横幅和卡片堆叠的社团展示模板。网站的价值既包括清晰传达内容，也包括可实际操作的连续视觉体验。

## 2. 核心体验流程

启动准备 → IXD Logo / 等待登录 → 身份验证与授权 → 加速 Welcome → 共享 Logo / 星门转场 → 银河星图 → 星体导航 → 星体详情 → 连续返回星图。

- 登录等待由用户操作结束，不能用固定时间自动越过。跳过开场仍进入登录区域；访客入口由用户明确选择，允许阅读公开内容。已有有效会话可便捷进入或选择重播开场。
- 成功路径保留 `ACCESS SYSTEM → AUTHENTICATING → IDENTITY CONFIRMED → PERMISSION AUTHORIZED → WELCOME TO IXD` 的关系；Welcome 沿用已确认的原动作并以 2× 节奏播放。
- 转场应把前一阶段的视觉身份带入下一阶段；星门呈现的银河与进入后的主页是连续空间。
- 详情服务于内容阅读，打开和返回都能看出星体的来源与归属。毫秒数、轨迹参数和响应式坐标由当前实现及专项验证维护，不在本文固定。

## 3. 视觉语言

- 共用 IXD 向量 Logo、既有比例与构成。开场、Welcome、星门和星图核心保持同一品牌身份，不任意换成通用科技图标或重新设计 Logo。
- 主体系为紫、蓝、青、冷白与蓝灰；银河保持深空背景、原有星云和星尘层次。保留 atlas 内少量局部暖色，不为“统一冷色”抹平空间细节。
- 无保存偏好时默认深色；明确保存的浅色选择应保留。浅色设置作用于相应系统界面，银河仍保持深空视觉。
- HUD、坐标、编号、细线、矢量轨道、稀疏星系节点与留白共同建立克制的系统感。界面文字和操作目标须可读、可辨识。
- 避免将页面改为通用 SaaS 登录卡、厚重卡片墙、大面积霓虹光团或无关炫技特效。原视频是参考和验证材料，不是可交互背景的替代品。

## 4. 动效原则

- 使用明确阶段与完成事件组织连续体验，避免独立定时器互相抢状态；快速重复操作、重播与尺寸变化也要能接续或安全取消。
- 共享背景不应随前景切换整层闪灭。已确认的局部文字显隐、色块展开和明暗关系不得被通用淡入淡出覆盖。
- Logo 跨场景保持视觉连续；星体从主页到详情再返回使用同一视觉身份，保留结构、种子、线宽关系及循环相位。
- 打开应从当前位置直接抵达实际详情布局位置，再展开终端；返回应连续抵达原节点，不以临时副本消失、原节点重新淡入替代归位。
- 动效表达空间和状态，不妨碍点击、键盘操作、焦点恢复与正文阅读。
- 减少动态效果模式保留必要状态反馈、导航和内容，关闭强扰动、闪烁及不必要的持续运动，不让流程停在动画等待中。

## 5. 银河交互原则

- 银河包含有深度差的云、远中近星尘；整体鼠标视差与局部尾流是不同层面的运动，应共同保持空间感。
- 局部扰动沿实际鼠标轨迹产生，具有历史状态。快速移动偏细窄、慢速移动偏宽；轨迹经过后继续尾流、卷动、扩散、惯性衰减并恢复。
- 停止或移出指针后不再注入新输入，旧扰动自然消散，不留下永久空洞、亮斑或持续堆积。
- 不能退化为跟随指针的放大镜、圆形光圈、单一径向扭曲或整屏平移；增强效果应保留原云图、粒子与恢复特征。
- 背景物理不得推散文字、HUD 或导航主星。节点艺术表现可以有克制视差，点击区域与阅读布局保持可靠。
- 具体求解器、网格大小、显示增益等是可验证的实现选择，不是永久设计规范；调整前先查当前状态和最新专项记录。

## 6. 星图与节点设计原则

一级主星为公告中心、赛事中心、项目广场、活动与沙龙、学习中心、作品与成果，另有 IXD CORE 与个人中心。六大专业方向 AI、机器人、新媒体交互、视觉与文创、XR、硬件归入 CORE 的二级星图，保留已完成的方向造型和内容。暗星表达尚未开放的空间，不伪装成已上线内容；二级图复用同一银河 renderer。

- 节点在统一 HUD 与星系语言内拥有可辨认的不同结构，不能全部套用同一种旋转圆环。
- 类型、内容、位置、视觉预设和种子集中由数据驱动；显示层读取数据，不在各组件重复维护社团文案。
- 主星、放大星体和归位星体保持相同结构与身份。响应式调整或途中关闭不得生成不同形态或重置循环。
- CORE 详情作为六方向星系的父层，只提供进入二级星图的主要入口；通过核心放大与内层星系中心展开表现进入，反向返回 CORE 详情，再单独退出到一级星图。二级方向位置稳定，不整体旋转或公转。
- 具体路由与视觉预设见 [star-map.ts](../src/data/star-map.ts)，运营正文以数据库发布版本为准。[club-content.ts](../src/data/club-content.ts) 保留原资料和幂等导入来源，本文不复制完整正文。

## 7. 登录与系统界面原则

登录是进入 IXD 系统的体验关口。平台使用真实服务端账号和可撤销的 HttpOnly Cookie 会话；公开内容允许访客查看，收藏、申请、报名与投稿等操作由服务端校验。成员身份与管理角色分开，不以视觉授权动画代替权限。

- UI 只收集输入并呈现结果，不包含固定密码、Demo 旁路或角色判断来代替服务端授权。
- 认证服务与展示状态分离，异步结果、取消、超时与服务不可用有明确反馈；登录成功接续已确认的授权动画。
- 密码、会话令牌不存浏览器 storage；开发随机凭据留在被 Git 忽略的本地文件。注册、邮箱验证、重置、密码修改、注销和停用形成真实闭环；生产不得启用测试邮箱或自动种子账号。
- 错误反馈留在 IXD 终端体系中，使用简洁的 `ACCESS DENIED / INVALID IDENTITY`，并允许重试。
- 密码查看使用可操作、可识别的图标按钮，提供辅助技术标签与切换状态，保留输入和选择位置；进入认证或重置流程时恢复隐藏。

## 8. 响应式与性能原则

- 桌面优先，移动端维持登录、星图选择、详情阅读、返回和设置的基本可用性；不以桌面固定坐标强行裁切手机界面。
- 保持有界 DPR、像素、粒子、纹理和 GPU 预算，复用几何与缓冲，避免逐帧分配、无限叠加粒子和大面积 blur。
- 低画质、自适应降级、页面隐藏暂停和减少动态效果各有职责，不通过统一去掉核心动效来掩盖性能问题。
- WebGL 不可用或上下文丢失时保留静态背景和可用 UI；不把成功进入网页等同于所有设备均达到相同帧率。
- 性能优化须验证原视觉与交互连续性，尤其是背景、Logo、尾流、星体旅程及音频节奏；生产包和实际浏览器行为都需要按改动范围验证。
- 沿用原生 TypeScript / Three.js / Vite 工程增量开发，保留原档案、美术、音频、画质基础和上游署名；不要因局部任务自动重建项目或更换框架。

## 9. 内容真实性原则

社团内容源自用户提供的 Word 初稿：当前星图主要依据 `IXD社团.docx`，早期档案内容依据 `IXD社团(2).docx`。可移植的整理结果及说明见 [club-content.ts](../src/data/club-content.ts)、[star-map.ts](../src/data/star-map.ts) 和 [content/README.md](../content/README.md)；本机原始 Word 路径不是 Git 仓库资源。

- 典型项目、成长路径、招募规模和活动建议属于规划或示例，不能改写成已完成成果、实际人数或正在运行的业务。
- 不虚构成员、获奖、比赛结果、已落地项目、活动日期、联系人或报名渠道。
- 竞赛是方向与选题参考，不代表已核实的当届日程或参赛成绩；新增这类事实须有可核对来源。
- 暂未提供的加入方式保持“待发布”或等价明确状态；浏览进度只表示本次页面探索，不冒充真实学习记录。

## 10. DO NOT CHANGE WITHOUT EXPLICIT USER REQUEST

以下已确认原则不得自行重构或“优化掉”：

1. IXD 系统启动、登录、Welcome、星门与银河星图的整体体验关系。
2. 共用 IXD Logo、冷色 HUD 与深空星系视觉；默认深色及尊重已保存主题选择。
3. 原 Welcome 动作的局部层次和连续 Logo 衔接，星体打开、详情、返回的共享视觉身份。
4. 具有历史、快慢差异、扩散、惯性和恢复的轨迹扰动；导航文字与主星不被物理推散。
5. 六大方向、功能星和暗星的数据驱动结构，以及节点之间可辨认的形态差异。
6. 开发与生产身份配置的清晰边界、集中认证模块、服务端权限，以及内容真实性约束。
7. 原生工程的增量维护、必要响应式、减少动态效果与回退能力。

这不是冻结每个文件、常量或动画毫秒数。符合上述原则的实现修复与性能改进应依据当前任务、代码和验证证据推进；仓库安全及操作授权统一遵循 AGENTS。
