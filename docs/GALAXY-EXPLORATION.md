## 四层天空

| 深度 | 实现 | 指针反馈 |
| --- | --- | --- |
| 最远：银河云带 | 本地程序生成的 1280×768 星云纹理，包含暗尘、冷暖云区和极远星光 | 最小 UV 偏移；推进时缓慢放大 |
| 远景：密星 | 1,900 个固定种子的点，部分集中在银河带中 | 远景透视位移、极轻闪烁 |
| 中景：亮星与星团 | 620 个较亮星点；界面上的星系由星尘、核心和轨道构成 | 更大的位移与邻近提亮；节点图形轻微漂移，命中区域保持稳定 |
| 近景：星尘 | 80 个近处粒子与最多 20 个池化尾迹 | 最大位移、指针附近的小幅排斥和淡出尾迹 |

云纹理只在首次进入时计算，之后只采样一张纹理；同一图稿也用于 WebGL 静态回退。没有网络图片依赖、后处理 bloom 或多重全屏模糊。默认共 2,600 个 WebGL 星点，5 次绘制调用，1 张纹理。手机、性能画质与减少动态效果会进一步降低密度。

相机保持平行，不做绕轴旋转。指针按指数阻尼跟随，横向最大约 ±0.28 世界单位、纵向 ±0.19。1920×1080 测试中从左侧移到右侧，四层代表性横向位移约为 11 / 26 / 48 / 82 CSS px。指针离开后回中；触摸浏览不模拟鼠标漂移。

节点只更新缓存的 12 个图形元素的合成变换，避免每帧修改继承到所有 SVG 星尘的 CSS 自定义变量。

## 进入与退出

节点和详情共用 `galaxyGlyph()` 输出的矢量图，进入时从实际被点击图形的位置与尺寸接续。

1. 点击后高亮核心、描出扫描环，其他节点淡出。
2. 约 1.1 秒内放大星系并经过画面中心，随后停在阅读区域旁；Three.js 相机同时从 z=10 推进到约 6.65。
3. 从星系引出数据连线，终端从连线端点沿细线框展开，正文错峰出现。桌面从星体旁展开；手机在上方保留小型星系、下方显示可滚动内容。
4. 返回先折回内容，收束扫描结构，再用约 0.92 秒退回原节点；恢复星图、键盘焦点和原滚动位置。

Esc 可在推进中反向退出，使用当前变换作为起点。连续 Esc、窗口尺寸改变、隐藏、重播与减少动态效果切换均清理未完成的动画。进入和退出期间底层导航保持 inert；终端打开后保留 Tab 焦点循环。减少动态效果直接切换，天空仅在必要时重绘。

## 性能边界

- 原有画质配置与像素预算保留，最高 DPR 2；性能/自动降级使用约 184 万像素预算。
- 低 CPU 核心数或低内存提示会自动进入较轻档位；连续两个 120 帧窗口平均间隔超过 28 ms 时再降低强度，单次停顿不触发。只影响本次天空的有效强度，不覆盖用户保存的画质。
- 点缓冲、轨道、星云纹理与尾迹池固定；帧循环不创建粒子或几何体。
- WebGL 丢失使用同一星云的 Canvas 回退，详情保持可用；恢复后重新启用天空。

本机 Windows / Edge 无头浏览器、1920×1080、DPR 1，连续 300 帧采样并排除前 30 帧：增强前静止中位数约 4.2 ms；增强后静止和持续指针交互的中位数与 P95 均约 4.2 ms。这里测量的是浏览器 rAF 间隔，用于本机前后回归，不等同于 GPU 独立耗时或所有设备的帧率。
