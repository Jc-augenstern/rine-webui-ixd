# IXD 权限与公开访问规则

这是平台实现和验收共同遵守的权限契约。数据模型见 [CONTENT_MODEL.md](CONTENT_MODEL.md)，代码类型与输入白名单见 [shared/platform.ts](../shared/platform.ts)。菜单隐藏只改善使用体验，API 必须独立执行本文件的规则。

## 1. 身份与角色

| 身份 | 允许范围 |
| --- | --- |
| 访客 | 社团介绍及有效发布的 PUBLIC 内容；不能收藏、申请、报名、投稿或查看个人通知。 |
| USER | 有权阅读的内容；自己的资料、收藏、意向、申请、报名、作品草稿和通知。 |
| EDITOR | USER 能力，加上 `editor_grants` 明确授予的内容类型、方向/资源和动作权限。默认没有全站用户目录、角色管理或所有私人信息。 |
| ADMIN | 全站内容、用户、授权、设置及审计管理。仍遵守字段投影、CSRF、乐观锁、文件安全和最后管理员保护。 |

社团成员身份是独立的 `member_status=NONE/MEMBER`，不自动跟随角色或兴趣方向。填写负责人文字、选择 AI 等方向或成为项目成员，都不会获得 EDITOR 权限。被停用用户的旧会话不能再执行已登录动作。

邮箱尚未验证的登录用户可读取自己的个人列表、通知并标记本人已读；收藏、意向、申请、报名、上传、投稿等业务写入要求邮箱验证。自己的业务历史不授予关联内容访问权限：成员降权、撤回或过期后保留本人记录与状态，隐藏不可见的标题、岗位、时间和地点。

首个管理员由受控 CLI 创建。禁止第一个注册用户自动成为管理员、公开管理员注册、前端固定密码或旧 Demo 旁路。开发账号使用本地随机凭据，与生产初始化隔离。

## 2. 三层授权

每个管理请求依次验证：

1. **功能**：当前角色及 grant 是否允许相应 kind 和动作。
2. **资源/归属**：指定内容、方向范围、用户拥有关系或所管项目/活动是否匹配。
3. **字段**：请求只包含该角色与动作允许改动的字段，不接受未经验证的数据库对象。

`editor_grants` 的字段为 `user_id/content_kind/direction_id/content_id/actions`：

- `content_id` 非空：仅指定资源；不能同时填写 `direction_id`。
- `direction_id` 非空：仅对应方向范围。
- 二者都为空：该 kind 的全范围，必须由 ADMIN 明确授予。
- 动作枚举：`create/read/update/publish/archive/delete/manage`；没有动作就没有对应能力。`manage` 用于该资源的申请、成员、报名等操作，不等于用户角色管理。
- 单凭拥有内容或出现在 authors 中不能取得 EDITOR 管理权限；USER 投稿通道是单独的受限例外。

方向授权在多方向内容上须保守处理：编辑者需要覆盖该资源的全部方向，或者有该内容的显式授权/该 kind 全域授权。否则只要给跨领域内容加一个 AI 标签就会把整条资源暴露给 AI 编辑者。无方向内容只接受显式资源或 kind 全域授权。

更新内容时验证原资源范围和变更后的目标范围；不能通过改 directionIds、所有者或关联资源把越权记录移入自己的范围。关联/附件选择器也只返回当前账号有权选择的记录。

## 3. 功能、资源与字段矩阵

| 操作 | USER | EDITOR | ADMIN |
| --- | --- | --- | --- |
| 读公开内容 | 满足有效发布与可见范围 | 同 USER；管理预览另需 read | 满足公开规则；管理预览允许 |
| 自己资料 | 显示名称、年级、专业、兴趣方向及资料版本 | 同 USER | 同 USER；管理操作单独端点 |
| 他人账号、邮箱、状态、角色 | 禁止 | 禁止全站访问 | 必要管理信息，分页/搜索/过滤 |
| 角色、停用、成员身份、授权 | 禁止 | 禁止 | 允许，审计及会话失效保护 |
| 六类内容、方向、路线、社团页面 | 不得走管理写接口 | 相应动作且资源范围匹配 | 全站管理 |
| 新建/修改自己的作品草稿 | 仅 DRAFT/RETURNED 等未发布可编辑状态 | 自己投稿同 USER；管理动作另需 grant | 允许 |
| 投稿进入审核 | 自己的未发布稿，状态由服务端控制 | 同 USER 或受授权管理 | 允许 |
| 发布/退回作品 | 禁止 | 有作品 publish/manage 等明确权限与范围 | 允许 |
| 收藏、意向、申请、报名 | 仅自己 | 自己；管理另走受权端点 | 自己；全站管理另走管理端点 |
| 审批申请、管理项目成员 | 禁止 | 该项目 manage | 允许 |
| 查看活动报名列表 | 仅自己报名记录 | 该活动 manage，仅必要字段 | 允许 |
| 站内通知与已读 | 仅自己 | 仅自己 | 自己通知；审计不等于读取所有通知正文 |
| 图片/附件上传与选择 | 自己投稿所需文件 | 自己文件及获授权内容引用 | 全站媒体管理 |
| 下载限制附件 | 拥有者或满足关联资源授权 | 同左，范围限制仍生效 | 管理用途允许 |
| 节点与网站设置 | 禁止 | 默认禁止 | 允许，路由/预设白名单 |
| 操作日志 | 禁止 | 默认禁止全站日志 | 允许安全日志投影 |

用户修改资料的字段白名单是 `expectedRevision/displayName/grade/major/directionIds`。不能夹带 `role/status/memberStatus/emailVerified/passwordHash`。密码使用专门接口验证当前密码；重置使用一次性令牌。

USER 作品请求仅接受内容字段，并把拥有者固定为会话用户。`state/reviewReason/ownerId/publishedVersionId` 等管理字段不能通过 payload 或 PATCH 混入。自己的已发布作品不能绕过审核直接改变公开版本。

项目/活动管理者只获得处理业务所需的申请说明、作品链接、显示名和必要联系方式；不因此获得用户的密码哈希、私信、全部通知或其他项目申请。

## 4. 发布与读权限

公开查询共同执行以下规则：

1. 内容不是 WITHDRAWN/ARCHIVED 且存在已发布版本，或明确安排的重新发布版本已到服务端计划时间；再次撤回/归档会取消该计划。
2. 未来计划版本在到期前不返回；现有公开版本继续可见。
3. 当前有效发布配置未过期。
4. visibility 从有效版本读取，而非最新 draft。PUBLIC 允许访客；AUTHENTICATED 需要有效会话；MEMBERS 还需真实成员身份。
5. 草稿、退回原因、内部审计与用户联系方式不进入公共 DTO。无权访问的内容不通过搜索、关联列表或附件链接间接泄漏。

管理预览必须另走受保护接口；“预览链接”不能使未发布内容匿名可见。栏目 enabled 只控制产品入口，不是权限机制；关闭栏目后直接链接要有清楚状态，不能报错崩溃或暴露私人数据。

旧方向 `#star/ai` 等链接可以兼容映射到社团介绍的二级方向图，不能借兼容路由绕过当前可见范围。返回、刷新和复制详情链接保持导航状态，与是否拥有读取权限分开处理。

## 5. 会话、CSRF 与用户停用

- 服务端使用成熟会话插件及 PostgreSQL store；浏览器只持有 HttpOnly 不透明 Cookie，不在 localStorage 放角色或认证令牌。
- 会话表只存会话 ID 哈希。会话 data 不保存可用作授权依据的旧角色；每次请求重新查询用户状态和授权。
- 登录与权限变化轮换或撤销旧会话。停用、角色撤销和 grant 移除立即生效，不能等用户刷新后台菜单。
- 生产启用 HTTPS、Secure、合适的 SameSite 和受控 Cookie 路径。开发前后台统一 127.0.0.1，并通过各自代理访问 API。
- Cookie 写操作执行 CSRF 与 Origin 校验，包括登录、退出和管理操作。GET 不改变业务状态。不能用任意来源凭据 CORS 绕过本地联调问题。
- 登录、注册、验证、忘记/重置密码和敏感操作限流。重置邮件不通过接口返回原始令牌；令牌随机、限时、一次性，成功重置撤销原会话。
- 邮箱缺少可用发送服务必须真实报错。本地邮件捕获服务只在开发配置下启用，不向真实用户发送测试邮件。

最后一名 ACTIVE 且邮箱已验证的 ADMIN 不得被停用、降级或删除；不能提升未验证邮箱的账号作为有效管理员。该检查和更新必须在同一事务内锁定共同管理员资源；单纯先 COUNT 再 UPDATE 不能防止两个请求并发移除所有管理员。

## 6. 并发与审计边界

内容/设置/资料编辑带 expectedRevision，冲突返回 409 并允许重新读取。审批带申请 revision；报名和收藏通过数据库唯一约束防重。

项目名额和成员状态、活动名额和报名状态用事务锁实现。仅禁用前端按钮无法防重复或超额。取消活动/处理申请的状态变更与通知写入同事务。

审计记录谁、何时、对何资源做何操作，使用字段白名单生成差异摘要。重大角色和权限变更、停用/恢复、审核、发布、撤回、删除及管理恢复操作必须留痕。不记录密码、完整 token、会话 ID、服务器密钥或无限制原始请求体。

角色授权和审计 API 的返回 schema 与数据库 users/sessions/token 结构分开，禁止直接序列化整行数据库对象。

## 7. 附件与缓存

上传者不能决定服务器文件路径。上传须验证字节内容、允许类型、大小、数量及使用权限；下载和引用校验不依赖文件名难猜。PUBLIC 文件也要存在有效公开引用才匿名提供；草稿内文件、MEMBERS 文件和 PRIVATE 文件不能绕过内容权限直取。

文件替换创建新媒体记录；历史/草稿/发布版引用受外键保护，删除失败提供引用说明。编辑者不能通过共享媒体库枚举别人的私人申请或未授权草稿。

API 响应使用适当的 `no-store`，Service Worker 显式绕过 API、后台和受限文件，后台导航不得被星图离线 fallback 接管。登录资料、报名/申请、用户列表、通知、重置令牌不放入 PWA CacheStorage。退出/换账号清理本应用内存用户状态及应用专属用户缓存，不清除无关站点数据。

## 8. 必须保留的反向测试

- USER 直接调用管理 API、修改自己的角色或投稿发布状态，被拒绝。
- 用户 A 猜用户 B 的资料、申请、通知、收藏和附件 ID，读写都被拒绝。
- EDITOR 修改范围外或多方向越权资源、借方向变化转移归属、给自己授权，被拒绝。
- 普通保存发布内容草稿不会改变公开正文、visibility、名额或通知版本。
- 停用账号、撤销角色/grant 后，旧 cookie 直接请求仍被拒绝。
- 最后 ADMIN 的并发停用/降级、并发最后一个名额审批/报名，不破坏约束。
- 缺 CSRF、伪造 Origin、危险 Markdown/链接、错误 MIME、路径穿越和私人附件匿名请求，被拒绝或安全处理。
- 注销并换用户后，前后台内存状态及生产 PWA 不泄漏上一账号的信息。

这些是验收要求，不代表已有绝对安全保证。生产上线仍需真实环境检查、管理员二次认证等加固审查和备份恢复演练。
