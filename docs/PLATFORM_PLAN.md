## 架构决策

- `src/` 保持原生 TypeScript / Three.js / Vite；原 renderer、尾流求解器、Logo 与星体旅程受保护。平台内容变化通过业务层更新，不重建银河。
- `admin/` 为独立 React / TypeScript / Vite 入口和构建，普通侧栏、表单、表格，不引入前台动画和音频。
- `server/` 为 Fastify / TypeScript 模块化单体；数据库访问只用 `pg` 和参数化 SQL，版本化 SQL 迁移，避免并用 ORM。认证、内容、协作、媒体、任务各自成模块。
- `shared/` 维护 DTO 与严格输入 schema。统一字段/状态后再并行实现，禁止各端各造一套数据模型。
- PostgreSQL 存运营数据、会话、任务、通知、审计；本地磁盘 Storage 存附件，不依赖 Redis 或微服务。
- 成熟插件处理 Cookie、服务端会话和 CSRF，Argon2id 存密码，SMTP 发送验证/重置信。开发仅连接本地邮件捕获工具。
- 六类内容共用“容器 + 不可变版本 + 草稿/发布/定时指针”，类型专属字段严格校验；项目岗位/申请/成员、报名、收藏等使用独立关系表与事务。
- 公开读取必须从可见的发布版本取值并在服务端过滤权限、定时与过期；草稿保存不改公开正文。乐观锁防止并发覆盖。
- 本地同用 `127.0.0.1`：前台 5173、后台 5174、API 3000；前后台通过代理访问同一 API。数据库和邮件工具仅绑定本机。实际端口以环境检查结果为准。
- 生产准备为同域前台 `/`、后台 `/admin/`、API `/api/v1/`，Compose + 反向代理 + 持久卷；不公开部署，不购服务器、不改 DNS。

依赖核对以官方资料和 npm 官方注册表为准，保留 lockfile，不整体升级既有 Vite/Three.js。主要参考：[Fastify 支持策略](https://fastify.dev/docs/latest/Reference/LTS/)、[pg 事务](https://node-postgres.com/features/transactions)、[Fastify session](https://github.com/fastify/session)、[CSRF 插件](https://github.com/fastify/csrf-protection)、[Argon2](https://github.com/ranisalt/node-argon2)、[SMTP](https://nodemailer.com/smtp)。
